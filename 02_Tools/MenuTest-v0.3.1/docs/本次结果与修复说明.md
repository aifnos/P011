## 2. 精确根因：CRCRLF

002-identity-stdout.txt 共 32 字节，实际内容：

```text
0\r\r\n\r\r\n__P011_REMOTE_EXIT__=0\r\r\n
```

实际十六进制：

```text
30 0d 0d 0a 0d 0d 0a 5f 5f 50 30 31 31 5f 52 45 4d 4f 54 45 5f 45 58 49 54 5f 5f 3d 30 0d 0d 0a
```

旧版 MenuLab/P011-MenuTest.ps1 使用：

```regex
(?m)^__P011_REMOTE_EXIT__=(\d+)\r?$
```

其中 \r? 最多接受一个 CR，不能处理这次实际捕获的两个 CR。对原始返回文本进行离线重放，旧规则匹配数量为 0。这是启动器的文本解析缺陷，不是密码错误、缺少 root、USB 超时或 QML 崩溃。

.NET 官方对行尾锚点及 CR/LF 的说明：
https://learn.microsoft.com/en-us/dotnet/standard/base-types/anchors-in-regular-expressions

这里只确认已经保存的 shell 文本为 CRCRLF；没有逐层追踪，不能确定是哪一层增加了额外 CR。

## 3. v0.3.1 修正

仅规范化 shell 文本的解析副本：CR+LF（包括重复 CR）变为 LF，孤立 CR 也作为换行。原始 stdout/stderr 保留，不处理镜像或二进制 ADB 数据。

每条 shell 命令使用独立退出标记；标记必须唯一、完整、位于末尾，退出码范围为 0..255。adb 进程失败和超时不能被标记覆盖，设备非零退出码仍会停止。原版哈希、root、父子进程及恢复检查不取消。

新增自动运行的 22 项 PowerShell 解析自检，在任何 ADB 调用前执行；结果保存 host-parser-selftest.json。每条 shell 调用另外记录规范化输出和 remote-status.json。

结果摘要补充失败阶段；明确没有请求启动候选时显示 NOT_SWITCHED，页面显示“未测试”，而不是暗示恢复失败或全部页面故障。

QML、资源补丁、设备端暂停/恢复/超时监督程序与 v0.3 逐字节相同，共核对 13 个相关文件。
