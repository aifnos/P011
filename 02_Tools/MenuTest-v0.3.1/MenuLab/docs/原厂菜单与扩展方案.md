# 碳氧 P011：原厂菜单、页面结构与功能扩展方案

## 结论

原厂菜单可以做有针对性的扩展。菜单入口不在 Android Launcher 或独立应用列表中，而在 `/usr/bin/Z03` 内嵌的 `NaviPanel.qml`。它使用两套固定 `ListModel`，由 `main.qml` 的 `sceneLoader` 加载页面。推荐第一步只在两套列表末尾各追加一个“工具箱”，工具箱及后续功能页从 `/mnt/data/p011-menu/` 加载。

本轮完成静态结构分析、原始 QML 恢复、可供离线生成的候选补丁，以及三个纯 QML 功能示例。**没有在学习笔上替换或运行候选 Z03；这不是已经通过实机验证的安装包。** 已通过实机验证的是此前独立运行的 PlayLab v1.2，而不是本轮嵌入原厂菜单的方案。

## 2. 原厂 UI 的总体结构

```text
Z03 进程
└─ qrc:/main.qml
   ├─ 完整画布：P011 分支 800×480
   └─ main 内容容器：800×268，位于 y=106
      ├─ inner：主页状态区域、答疑/查词模式切换、NaviPanel
      ├─ sceneLoader：普通功能页
      ├─ wordView：常驻 ZybScanWordView2，默认隐藏，z=100
      ├─ SetShortMenu：快捷设置抽屉
      ├─ 全局键盘、提示、网络/电量弹窗
      └─ 扫描、录音键、拍照键、来电等全局事件
```

依据：`main.qml:25–42,104–126,312–391`；`ZybQmlFiles/Style/Style.qml`。此前独立 PlayLab 已验证的 800×480 / y=106 / 800×268 与这一布局相符。

`main.rotation` 随 `devManager.isLeftHand` 选择 180 或 0。因此嵌入 `main` 的新页面默认继承原厂左右手切换。**新的子页面只需 `anchors.fill: parent`，不要再写 `y=106`，也不要照搬独立 SDL 程序的旋转处理。**

### 2.1 普通页面路由

```text
NaviPanel 中点击图标
  → navi.sceneSource = model.source
  → main.qml 的 onSceneSourceChanged
  → sceneLoader.source = sceneSource
  → 隐藏 inner，禁用快捷抽屉拖动
  → 已创建的 scene.parent = main，scene.anchors.fill = main
```

返回首页主要通过 `UILogic.backToHome()` → `main.close()` → 清空 `naviPanel.sceneSource`。修改 Loader 的 source 会卸载原来的页面；不要把页面内部 Timer 当作自动常驻后台服务。

依据：`NaviPanel.qml:134–169`；`main.qml:312–391`；`ZybQmlFiles/Funcs/UILogics.js`。Qt 的 Loader 文档也明确说明 source 改变或清空会销毁此前创建的对象；本机具体行为仍以这里的 QML 实现为准。

### 2.2 查词页面是特殊分支

菜单中的 `ZybScanWordView2.qml` 并非每次都走普通 sceneLoader。`main.qml:317–323` 会清空 sceneLoader，设置常驻 `wordView.showType="scan"`，显示 wordView 并切到提示页。

所以更改查词流程时必须同时考虑常驻对象、可见性变化和全局扫描回调，不能把它当作普通新建/销毁页面。

### 2.3 pageType 不是装饰字段

`main.qml` 根据 `scene.pageType` 判断当前是否已在拍照、答疑、语音或通话页面。与业务模式混用会使系统对自定义页面执行它没有实现的方法或属性操作。

建议自定义页使用独立值：

```qml
property string pageType: "p011toolbox"
```

不要为省事写成 `"camerapage"`、`"picSearchPage"`、`"voicetranspage"` 或 `"phone"`。依据：`main.qml:632–697,977–1079`。

### 3.3 会影响添加功能的细节

**模式选择：**`getScanForWhat()===0` 选择 dictMode，另一分支选择 tidMode；切换通过 devManager setter 和 saveConfigFile 保存。依据：`NaviPanel.qml:95–106`，`main.qml:130–155`。

**标签可能动态变化：**`updateTidTitle()` 将头两个答疑标签更新成“扫描/识题 + getNetMainTitle()”。因此表中写的是资源初始标签，不应强行断定当前设备实际显示的每个字相同。依据：`NaviPanel.qml:19–22`。

**实际路由依据是 source：**`type` 字段不是唯一标识，也不是应用包名；语音翻译和语音通话都使用 type=4，但实际进入不同的 source。

**它不会扫描 /usr/bin 或 apps 目录：**菜单使用固定 ListElement，复制一个 Python、Shell 或 QML 文件到设备，不会自动出现图标。

**索引被硬编码：**设置红点使用 `tidMode[6]`、`dictMode[5]`。第一版自定义入口应追加到两套列表的末尾，而不是插入原列表中间。否则必须连带重构红点定位。依据：`NaviPanel.qml:25–92`。

**显示是横向滚动：**delegate 宽 96，ListView 横向、间距 80；追加后可能需要向右滑到末尾，不能因首页没立刻看到就认定入口失败。依据：`NaviPanel.qml:134–181`。

## 4. 八类主功能及其页面链路

### 4.1 扫题答疑

入口先是 `ScanTipPage.qml`，展示扫描提示；真实扫描信号由 main.qml 接收后，进入 `ScanPicPage.qml`。

```text
ScanTipPage（初始提示）
   └─ 笔头扫描信号 → main.qml
       └─ ScanPicPage
          ├─ ScanPicContentPage：提示/扫描中/扫描结束
          ├─ ApiResultPage：答疑结果
          ├─ 无权限/无结果等状态
          └─ ResultPrintPage：打印结果
```

关键对象：`scanManager`、`ocrManager`、`apiNetWork`、`dataManager`。`ScanPicPage` 的 pageType 是 `picSearchPage`，页面销毁时有停止查询等清理逻辑。页面出现不代表模型、题库或服务端返回已经可用。

**扩展方式：**优先在结果页增加“导出图片/结果”按钮，复用已返回的数据；不要把新增离线工具硬套到 picSearchPage，以免扫描键驱动它的 pageState。

### 4.2 识题答疑／拍照

`CameraPage.qml` 的源码状态为：

```text
PhotoCapture → PhotoPreview → ResultPreview
                          ├→ NoPermission
                          └→ NoResultPreview
结果相关分支 → PrintPreview
```

子组件包括 `PhotoPreview.qml`、`ApiResultPage.qml`、`MoreResultPage.qml`、`ResultPrintPage.qml` 和视频/拖动裁切组件。`cameramanager.startCapture()` / `stopCapture()` / `takeOnePic()` 负责原生采集，`frameProvider` 对接图像，`apiNetWork.sendApiSearchQuesResults()` 对接题目查询。

**扩展方式：**先从照片已有数据的导出或离线查看做起。摄像头页面会在销毁时停止采集；新功能要保留这些释放动作，避免与原厂摄像头争用。

源码另有一次 `"printPreview"` 赋值与声明的 `"PrintPreview"` 大小写不同。这里只记录静态不一致，不替用户修改，也不据此断言实机该按钮一定失效。

### 4.3 扫描查词

实际入口是带 **2** 后缀的 `ZybScanWordView2.qml`。旧 `ZybScanWordView.qml` 和其他旧结果页也在资源里，但不是当前菜单默认入口。

```text
常驻 wordView
  ├─ 提示页 / 扫描页
  ├─ ZybScanWordResultPage2
  │  ├─ 汉英/英汉容器
  │  ├─ 作业帮、简明、牛津、新华、现代汉语、成语、文言文等控件
  │  ├─ GradeSelectDialog：学段选择
  │  ├─ FollowUpView：跟读及相关结果
  │  └─ 更多释义、描红、题目等扩展子页
  └─ 历史/收藏点词后也可复用这一常驻视图
```

关键对象：`QueryWordManager`、`scanManager`、`WordHistoryManager`、devManager 及部分 API。`wordView` 的显示/隐藏负责终止查询、停止播放、清理临时视图及调整自动熄屏。

**扩展方式：**自建“生词卡/笔记导出”应在现有识别字符串或词典模型之后接入，不应为显示一个词就重新启动整套扫描引擎。模型和词库还有 aisdk 分区依赖，本轮 QML 不等于完整词典 SDK。

### 4.4 语音翻译

`VoiceTrans.qml` 状态是 `SoundTip`、`SoundListen`、`SoundNoRes`、`SoundRes`，分别加载提示、录音中、无输入/无结果和翻译结果组件。依据 Style.highVersion 选择部分横竖版子组件。

它调用 voiceManager 初始化、开始/停止录音，使用 websocket / API 发送音频和接收结果，退出时释放录音、关闭连接、停止播放。从麦克风实体键进入和从菜单进入存在不同初始化路径。

**扩展方式：**“本地录音器”需要单独设计音频占用和文件保存，不能仅改此页标题就把在线翻译变成离线录音。先保持原录音释放逻辑。

### 4.5 语音通话

`Phone.qml` 声明 `ready`、`ring`、`incoming`、`calling`，另有 `PhoneRecord.qml` 通话记录和登录/绑定提示页面。调用 `sslClient`、`phoneA2BManager`，包括 Agora 相关方法及账号/家长对象。

**这份代码支持的是厂商应用的通话流程证据，不足以证明它是标准手机拨号器或可任意拨打蜂窝语音号码。** 本轮自定义菜单不更改登录、绑定和服务权限。

### 4.6 生疏归纳

`StoreView.qml` 包装两组列表，默认 state=`word`：

```text
StoreView
  ├─ WordStorePage：收藏词条
  └─ StorePage：收藏题目/图片及批量操作
```

词条由 WordHistoryManager 等模型提供，题目由 dataManager / API 模型提供；点词可重新打开常驻 wordView，题目详情复用答疑结果及打印流程。

**扩展方式：**适合新增按用户选择导出 TXT/CSV/Markdown 的动作。不能假定页面模型就是一个任意可读 JSON 文件；应先核对原生模型的数据角色和持久化路径。

### 4.7 历史记录

`HistoryView.qml` 同样默认 state=`word`，由 `WordHistoryPage.qml` 和 `HistoryPage.qml` 分别处理词语及题目历史。与生疏归纳共享一部分结果重放、收藏和打印逻辑，但不是同一份列表简单改标题。

**扩展方式：**先做只读列表导出和筛选；删除、批量清空、同步等操作必须保留原有确认，不在实验页中默认执行。

### 4.8 设置

`SetMainPage.qml` 使用 GridView 显示 16 个入口；点击执行 `stackView.push(model.source)`。P011 的 cellWidth 为 258、cellHeight 为 80。主设置页销毁时还会停止蓝牙扫描、保存配置、刷新主页设置红点。

下列设置子页多数通过 `UILogic.backToSetPage()` 返回，后者会关闭当前主路由，再重新载入设置首页。**不能假定整个应用已有通用、可任意复用的 Android 式页面返回栈。**

### 5.1 隐藏调试页

`SetDevInfo.qml` 的 SN 连点触发键盘，验证成功显示 `SetDebugPage.qml`。隐藏页包含 ADB 和测试服两个开关。ADB 已成功启用，不需要修改它来安装新的菜单功能；“测试服”并不是自定义扩展框架，也不应改动。

### 5.2 快捷设置抽屉

`SetShortMenu.qml` 另有一套快捷控制：**音量、亮度两条滑杆，以及 WLAN、4G、自动发音、蓝牙四个开关**。打开时加载当前值，关闭时保存变化。它独立于 NaviPanel 与设置 GridView，不要只改 NaviPanel 就期待快捷抽屉同步出现新开关。

### 5.3 初始化/帮助页面

`ZybInit/` 下还有 InitView、GuidePage、NetSelectPage、AgreementPage、LoginPage、ActivePage 等。它们处理首次引导、网络、协议和激活，不是日常菜单入口。增加个人时钟/计时器无需改这条流程。

## 6. 如何给菜单添加自己的功能

### 6.1 推荐：一个固定“工具箱”入口 + 外部 QML 功能页

```text
原厂 Z03 中的 NaviPanel（仅追加入口）
      ↓
file:///mnt/data/p011-menu/ToolboxPage.qml
      ├─ ClockPage.qml
      ├─ TimerPage.qml
      ├─ DeviceInfoPage.qml
      └─ 后续追加计算器、卡片、阅读器等
```

第一步在 tidMode 和 dictMode 的最后各追加：

```qml
ListElement {
    name: qsTr("工具箱")
    type: 90
    icon: "qrc:/images/main_set.png"
    icon_high: "qrc:/images/main_set_high.png"
    source: "file:///mnt/data/p011-menu/ToolboxPage.qml"
}
```

示例暂借原厂设置图标，不引入新的图像资源；后续可改成同一专用目录内的本地图标。没有重用原有菜单项、没有移除原有功能。由于追加位置在末尾，原固定下标保持不变。

点击之前增加仅针对新 URL 的组件状态检查：文件缺失或编译失败时显示提示，不先切掉主页。但 **Component.Ready 只检查组件已准备，不保证实例化过程和每个子页永远不会报错**，还需要真机运行与日志确认。

### 6.2 新页的布局和返回约定

```qml
import QtQuick 2.10
import "qrc:/ZybQmlFiles/Style"
import "qrc:/ZybQmlFiles/Funcs/UILogics.js" as UILogic

Rectangle {
    anchors.fill: parent
```

### 6.3 为什么不能直接复制 NaviPanel.qml 就生效？

实际加载的是 `qrc:/NaviPanel.qml`，不是 `/usr/bin/NaviPanel.qml`。QML 被嵌入 Z03 的 Qt 资源数据中，而且该条目经过 zlib 压缩。

可行路线的比较：

| 路线 | 前提 | 本机当前结论 |
|---|---|---|
| 从完整源码重新编译 Z03 | 需要完整原厂工程、SDK、注册对象代码 | 当前没有这些完整源码；不能把恢复出的 QML 当作整个工程 |
| 外部 rcc / 资源重定向 / URL 拦截 | 应用需要主动注册或加载相应扩展，或另写兼容桥接代码 | 未发现“把 rcc 放目录就自动加载”的接口，不把猜测当作现有机制 |
| 修改副本中一个已定位的压缩 QML 资源 | 精确原版本、资源偏移、大小与校验；需可回退运行测试 | 本轮已完成离线候选构建与全部资源比对，尚未上机 |
| 另写完整 Launcher | 要自行维护原厂功能的上下文、资源与生命周期 | 工作量更大，不作为第一步 |

Qt 官方资源文档区分“嵌入可执行文件的资源”与“应用主动加载的外部资源文件”。本轮采用的是版本固定的资源副本修改，不是宣称存在通用插件扫描器。

## 8. 三种功能接入难度不能混为一谈

### 8.1 纯 QML 工具：最适合第一版

时钟、计时器、计算器、静态说明、手动单词卡等可直接放到工具箱子页。复用原 QtQuick、字体、Style 和父容器，不额外创建 Wayland 窗口。需要网络/文件持久化时另行设计接口。

### 8.2 把已跑通的 Python/SDL PlayLab 从菜单启动

不能写：

```qml
source: "/tmp/p011-playlab-v12/p011_lab.py"
```

Loader.source 表示要实例化的 QML URL，不是 Shell 命令。QML 没有因为设备 root 就自动获得任意 `system()` 函数。

需要一个与 Qt 5.10.1、ARM32 hard-float 匹配的原生桥接层，将少量白名单方法暴露给 QML。例如 `launchTool("playlab")` 是**建议新实现的接口名，不是已经发现的原厂方法**。后端固定路径和参数，使用 QProcess 异步启动，并返回退出信号；不能直接拼接用户文本作为 Shell 命令。

仅在二进制里发现 QProcess 符号，不足以证明原厂已经导出可供 QML 调用的通用进程启动函数。需要核对 public slot / Q_INVOKABLE 注册或新增自己的兼容模块。避免同时运行两份 Z03；外部工具退出后应恢复原页面焦点。

### 8.3 自定义 H5 页面

原厂 `ApiResultPage.qml` 已使用 WebEngineView，加载 `qrc:/zyb.html`、`qrc:/zyb2.html`，以 WebChannel 连接原生对象。可以借鉴已有用法设计自己的本地网页宿主，但仍须确认 QtWebEngine import 版本、视图生命周期、返回和权限。

不要把任意不可信网页接到原厂 API 对象或 root 命令桥。第一版只加载自己的固定本地页面，不修改厂商服务地址、登录或会员判断。

## 9. 必须保留的生命周期与回退条件

**实体键和扫描会抢占页面。** main.qml 的扫描、录音键、拍照键、来电处理在当前页面外层；进入自定义工具箱并不屏蔽它们。纯 UI 页可以随 Loader 销毁，摄像头、录音、后台任务页则需要显式清理。第一版不更改这些全局处理。

**原厂 Z03 被启动脚本循环拉起。** `/usr/bin/zyb_z03_launch.sh` 使用 while 循环、启动 Z03、wait 后再启动。单独杀掉 Z03 不会可靠停止整个启动链。直接再启动第二份候选也可能争用摄像头、音频与服务连接。

**首次测试用副本，不覆盖 /usr/bin/Z03。** 建议后续单独编写受监控的短时测试：识别真实启动脚本与父子进程，暂时抑制循环重启、正常结束当前应用、用相同 HOME/XDG_RUNTIME_DIR/工作目录运行候选副本，超时/崩溃自动恢复原链。要先把恢复动作做可靠，而不是先持久替换启动脚本。

这一受监控运行器本包尚未提供。不要自行把后台 `&`、killall、重挂载、cp 覆盖组合成永久安装操作。

**通过短时测试之后再考虑持久化。** 验收项应包括：两种主菜单、工具箱返回、原厂查词/答疑/语音/相机、实体键切换、左右手模式、待机唤醒、缺失扩展目录时的失败处理。Root shell 不代表任意修改后的启动镜像都可以启动。

## 10. 推荐实施顺序

第一版：保留全部原菜单，在两套菜单末尾增加工具箱；工具箱内只放时钟、可退出计时器、设备版本页。

第二版：稳定后加入自己的计算器、单词卡、阅读工具，维护外部 QML 目录；调整菜单文字或图标时先重新离线校验。

第三版：需要启动 Python/SDL 或导出原厂扫描数据时，再实现白名单原生桥和进程/扫描资源管理。它与“新增一个菜单按钮”不是同一工作量。

## 附：本包内容与使用边界

`source-original/`：191 个恢复的原始 QML、2 个项目 JS、2 个 qmldir、原厂启动脚本。仅是资源/脚本，不是可独立编译的完整 Z03 工程。

`docs/菜单源码导航.html`：内置源码、行号、全文搜索和菜单结构，双击离线打开，无网络请求，不执行任何 QML。

`docs/qml-catalog.csv/json`：静态索引，含界面文字、pageType、QML 引用、对象方法调用、状态声明。

`examples/device/`：工具箱、时钟、计时器、设备信息 4 个自写 QML 原型。

`patch/`：可阅读菜单改动、实际嵌入文本、资源块与固定版本清单。

`tools/`：本地候选构建工具；`tests/`：可复现离线验证脚本和本轮实际测试结果。包中没有自动推送/替换/启动原厂程序的安装器，没有字体文件，没有修改固件镜像。
