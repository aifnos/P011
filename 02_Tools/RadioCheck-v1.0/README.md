# P011 Wi-Fi／蓝牙只读诊断 v1.0

本包用于排查 ToolsTest v0.4.3 运行后 Wi-Fi 无法启用、蓝牙行为异常，以及原厂进程恢复未确认的问题。它不是新一轮工具箱试验，也不是刷机或一键修复程序。

## 运行

将本包完整解压到 `D:\project\P011`，得到 `D:\project\P011\P011-Radio-Check`。

学习笔保持当前开机状态，保留 root ADB，只连接这一台设备。不要再运行 ToolsTest 的 START。

双击 **START.cmd**。不需要输入 PowerShell 命令。通常约 20～60 秒；若读取超时会保留部分结果，整个设备采集过程按阶段限时。电脑端 ADB 采集等待上限约 125 秒，其他准备和拉取另计。

这次采集期间暂时不要切换无线开关。它会查询：

- ConnMan、BlueZ、wpa_supplicant、oFono 的系统 D-Bus 名称是否存在、对应 PID。
- 服务存在时，只向其当前 unique owner 发固定的读取请求；服务缺失时不请求自动启动。
- Wi-Fi 网卡是否存在、管理标志/运行状态、IP、RFKill soft/hard、HCI 信息。
- 原版/候选 Z03、原厂启动循环、测试监督进程的 PID/启动时间/状态/等待位置。
- 原版主程序及启动脚本的哈希；ConnMan/蓝牙程序哈希与启动脚本。
- 筛选的内核/系统无线日志、ConnMan 等崩溃文件的名称/大小/时间；不复制 core 内容。
- 最近几个 MenuTest 会话的恢复记录；不会执行旧会话代码。

结束后在资源管理器中选中结果 ZIP：

`D:\project\P011\results\P011-RadioCheck-current-时间.zip`

详细记录位于 `D:\project\P011\logs\RadioCheck-current-时间`。

## 原厂重启对照

先保留当前结果。随后按学习笔正常方式重新启动一次，**不要恢复出厂，不要再次启动 ToolsTest**。从原厂设置里检查 Wi-Fi、蓝牙开关及搜索。

若问题仍在，或需要对照结果，双击 **AFTER-REBOOT.cmd**。它做的是相同的只读采集，只更换 `after-reboot` 标签，**这个文件本身不会重启设备**。

将前后结果包一并上传，并说明：

- 普通重启后 Wi-Fi 能否启用并搜到网络；蓝牙能否启用/发现/连接，而不是仅看开关图标。
- 期间是否只是运行工具箱 START，还是另外使用刷机工具写过 system、wcnmodem、NV 等分区。

## 边界与隐私

只在设备新的 `/tmp/p011-radio-check-时间/` 内写入本包脚本和诊断结果。不会改任何无线配置、USB 配置、原厂程序/启动脚本、分区和 NV；不会扫描/配对、开启 SSH、停止系统进程或执行重启。超时只处理本采集器自行启动的读取子进程。

标准库 `json` 在本机缺失，本包使用已有的项目内 JSON 输出模块，不安装或升级 Python。需要已有的 `python3` 和 root ADB；D-Bus Python 扩展不可用时保留错误并尝试有限的总线名称查询。

不读取保存的 Wi-Fi 密码文件、SSH 私钥、蓝牙 link keys、用户数据库、进程完整环境或二进制 core。系统日志仍可能含 IP、SSID、设备标识，自动遮盖部分密码格式和 MAC 不能保证清除所有个人信息，分享前请检查。

这个程序不宣称“只要采集成功就代表无线正常”，也不自动启动/重启 ConnMan。先确认当前服务状态和启动配置，再决定是否进行有针对性的恢复。

## 验证范围

`tests/validation.json` 包含实际执行的 14 项 Linux 主机测试：Python3.5语法、缺失json、进程stat解析、JSON输出、有限超时、模拟D-Bus只读请求及隐私过滤等。Windows启动器复用已在本项目使用的参数引用、独立退出码和CRCRLF解析，并在运行前执行解析自检。

**新的采集器尚未在 Windows/P011 上实机执行。** 测试记录不是设备上无线功能恢复保证。
