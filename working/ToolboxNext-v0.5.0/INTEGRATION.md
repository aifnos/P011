# v2.4.0 集成契约（本候选尚未挂入原厂菜单）

当前功能代码和目标 Python 后端自检通过；这不是设备 UI 安装说明，更不是自动 START。

## 入口与生命周期

1. 新版适配层只在独立候选中提供 `device/ExtensionPage.qml`；继承父页面的 800×268 内容区，不加 y=106 或旋转。
2. 适配层启动一个由监督进程拥有的 `State('/mnt/data/p011-user')` 和回环 `BoundedServer(('127.0.0.1',0),state)`。不调用任何原厂 D-Bus 控制接口。
3. Qt 上下文提供 `nextEndpoint`、`nextToken`；令牌只驻留内存，不放 URL、命令行、可读菜单文件或日志。也可在创建 QML 组件时通过可信内存桥传入 `endpoint`、`token` 属性。现有 `server.py` 命令行入口**故意不会输出令牌**，不能单独启动它再期待界面自行连接。
4. `exitRequested()` 由父加载器处理；页面切换会暂停游戏、保存分数、停止自己启动的媒体，销毁时中止待处理 UI 请求。最终候选结束必须先关闭 HTTP 接口，再调用 `state.close()`，关闭本候选文件句柄/音频/采样及传输服务。
5. 无线传输只由笔上用户显式开启。离开文件页不延长 600 秒期限；整个候选退出时立即关闭。不得改成开机常驻或自动 `0.0.0.0` 监听。

## 首轮设备验收清单

- 800×268 真机显示、四角触摸、返回/切页，三个游戏启动、暂停、最高分重入可见。
- 手机同一可信 Wi-Fi 实际上传/下载（不是电脑回环测试）；关页与退出后的传输生命周期，十分钟自动关闭。
- MP3 起步零位、声音、停止按钮、连续进度、自然结束、退出后无残余播放器；当前 QML 使用 `double` 播放代号，防止毫秒级时间戳被 32 位 `int` 截断。
- 视频 QtMultimedia 插件、格式/解码能力及声音；缺插件只影响视频，不应阻断文件页。
- 真机曲线、网络接口切换、进程列表/采样导出；只采样 `/proc`，不触碰 ConnMan/BlueZ。
- 原厂界面恢复与用户确认。只有这些逐项通过后才可将候选提升为“实机已验证”；常驻安装另行评估。
