1. 修复的因果断点

原 State bridge 在 min(Session._task_deadline, Handoff.deadline) 退出并发 CANCEL，
但 Parent 原启动只传 --ttl 300；F 稍后首次发行 issued_at+300。
CONNECT 在 INIT ready 后才发送，不能依靠 CONNECT 或及时 CANCEL 约束首次 RF。
本候选把原绝对 cap 在首 RF 前传入首次发行；没有把剩余时间换成新的 TTL。

2. 实际接线（保持原 owner/worker/clock/epoch）

ParentExecutor.start(ttl=300) 无新增公开期限参数。
仅已绑定实际 ReceiveConnectHandoff 的 Parent，在原 State.lock 中复核 Handoff，
捕获 Session._task_deadline 与 Handoff.deadline 原值，保留对象/clock/op/epoch，
生成 min 原 cap 的 repr(float) 文本。spawn 前再次复核同原件，不能从 UI/HTTP 取新 until。
无 Handoff 的独立 HOST 调用保留原 7 参数路径；不构成 State 接收准入。

私有启动参数顺序：
  python -B executor --execute-client-init --run-token TOKEN
  --manifest-sha256 SHA --ttl 300.0 --parent-until CANONICAL_FLOAT_TEXT

main 仅接受固定 7 或 9 参数；9 参数只允许 execute，严格解析有限正数及 canonical repr。
实际 F actor argv digest 包含相同两个新增参数，顺序与 Parent 原 Popen 参数一致。
F Loader/read_self 取 min(原局部期限, 原 cap)，但不据 cap 或哈希宣告无线权限。
F assemble -> Provider assemble -> Store 私有 _parent_until_v33 原件，均在 lease.start 前。

TwoPhase start 仍只接受 exact profile 最大 TTL：trial20 或 formal300。
准备期取 min(now+PREPARATION_SECONDS, 原 cap)。
首次一次 issued_at 后取 min(issued_at+固定 profile max, 原 cap)，再保存 prepared。
后续 Journal/watchdog/native producer 沿用同一个 deadline，不再 now+300。

cap=None 保原独立路径；trial profile 非 None cap 拒绝。

watchdog 仍只 --until 原 record.deadline，不接受 --parent-until 额外参数。
为传递原 float 精度，原十进制格式兼容仍在，同时允许 exact repr(float)（包括科学计数）。
watchdog 原 remaining<=300 检查保留，不新发 active deadline。
