Actual target task and write boundary
  Original 120-second stage cap is captured once before the first factory.
  StaticStagingTask retains that original deadline, worker, PID and clock.
  Each of two private original cd4c ReadonlyBaselineOwner phases gets exactly
  min(original_stage_until, once_phase_now + 30); collection stays original 10s.
  Each owner is constructed within this same task and retained before collect.
  No saved PASS, deserialized snapshot, external owner or approval bool is an
  input. Original return identity, neutral Store/Proc accounting, stock/device
  platform, PENDING before/after and actual collector/Proc inventory closure
  are checked. Full original Snapshot.key must remain equal across both phases.

  StageOwner is constructed after the first original read closes and is retained
  by the task before any Stage syscall. It uses existing FixedTmpAnchor and
  actual parent FD/inode/uid=gid=0/mode0700. The fixed rfinit ROOT must already
  exist with safe ownership/mode; it is not created, repaired or chmoded.
  Up to 4096 original names are observed with anchored nofollow metadata,
  including mtime/ctime. No old child subtree is opened or traversed. At least
  one free entry slot is required before new creation.
  Only client-<new 32hex token> is mkdir-created under that original parent FD.
  EEXIST fails; an existing run is never opened as the new owned run.
  Only its runtime/native/ctrl directories and fixed source/WPA/static records
  are created. Files use EXCL/NOFOLLOW/CLOEXEC, hashes, full byte readback/fsync,
  fixed 0400 source/record or 0500 native mode, and once-close plus actual EBADF.
  Global PENDING is additionally probed under the authenticated tmp FD.
  Final root set must be original entries plus exactly the new run; every old
  entry metadata must remain identical. Only directory identity is compared
  for the parent itself, since our mkdir legitimately changes its link/time.
  New layouts and sealed file metadata are checked again after the second
  native read. All retained original FDs close once, even when the task is late.
  Static success is set only after actual closure and the final original cap.

Failure and publication
  Any unknown, late return, changed baseline/entry/alias or native close failure
  rejects static success. Partial NEW files/directories are retained; no rm,
  recursive cleanup, overwrite, automatic restart or second staging attempt.
  Original raw stdout/stderr, HOST return/timeout, remote exit and STARTED marker
  are distinct. Non-return saves original exception privately and explicit
  empty/not-observed placeholders, not fabricated zero exits. Only exact whole
  payload echo and CRCRLF/CRLF are normalized in derived views; raw is preserved.
  Public ZIP has result.json/source-pins.json/README.txt/SHA256SUMS.txt with CRC
  and byte readback. Identifier/IP/process/old-entry/raw source evidence stays
  private. The physical new run token is private, not a public ready capability.

Explicit limits and remaining work
  No device-wide flock/exclusive lease is acquired. Fresh baseline/PENDING/entry
  observations do not prove atomicity or absence of all concurrent root writers.
  The code does not read old subtree content and cannot certify all its bytes;
  it never targets those subtrees for a write. Concurrent observed changes fail.
  candidate.json/static-source.json are not deployment.json. There is no GATT
  binding, LoadedDeployment, Handoff, Parent/F/watchdog launch, RF grant,
  Receive-root creation, device recovery/restore proof or Xiaomi phone result.
  device_exclusive_lease/rf_admission/source_factory_ready/deployment_available/
  send_available/receive_available/phone_tested remain false.
  Future formal execution must independently acquire its original locks, fresh
  complete baseline/identity/source graph and authenticated deployment/handoff.
  Root-reviewed SOURCE/checker or static staging PASS cannot replace that work.
