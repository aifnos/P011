## 此轮定位并修正的问题

1. 目标 Python 缺少 `http.server` 所需的 `html`、`socketserver`、`fcntl`：改为固定用途的最小 HTTP 子集；私网地址用固定只读 `ip -o -4 addr show` argv 获取，不运行 shell、不调用 ConnMan。
2. HTTP 实现限制四个工作线程、请求头 16 KiB、单文件 64 MiB、首部/正文超时、单连接单请求；拒绝重复认证/Host/长度头、chunked、跨站 Origin、路径穿越、符号链接、隐藏目录、执行型上传。关服中断上传不会发布半文件。
3. Windows 主机 QtMultimedia QML 插件无法加载：视频改成按需创建独立组件，缺视频插件不再导致整个文件页失败。目标视频解码仍未验收。
4. QML 播放代号为毫秒级时间戳：使用 `double`，避免 32 位 `int` 截断后无法匹配后端；音频仅一个在途轮询，仍读取真实 gst-play 位置。
5. 最高分失败写入不提前更新内存，避免后续重试被“分数未提高”短路；新增故障注入测试。暂停/返回时保存，进行中每五秒只在最高分提高时保存。

早期主机测试与失败记录保留，不改写为成功：包括缺 QtMultimedia 的页面加载失败、一次未中断完的上传、Linux 提前拒绝请求后的 TCP reset，以及目标 helper 错误调用输出型 JSON 库的 `loads`。最初 ADB stdin 读取 EOF 不可靠造成主机超时；改为明确归属的临时脚本，最终检查无遗留读取进程/目录。成功结论只依据上面的最后一组日志。
